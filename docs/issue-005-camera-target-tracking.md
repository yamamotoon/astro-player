# Issue #005: 天体が動くようになったことで、カメラの注視点が追従しない問題

## 状態

**要件合意済み（未実装）。次は実装。**

## 背景（issue #004との関係）

issue #004で太陽・地球・月の位置が時間とともに実際に動くようになった（円軌道の公転運動、
月/年モードでは特に大きく動く）。これにより、それ以前は問題にならなかった前提が崩れている。

## 現状（コードを確認した事実）

`scaleModel3d.ts`でカメラの注視点(`controls.target`)を設定している箇所は以下のみ:

- 初期化時: `this.controls.target.copy(EARTH_POS)`（コンストラクタ、[scaleModel3d.ts:179](../src/scaleModel3d.ts#L179)）
- `moveCameraTo(target, distance)`: `this.controls.target.copy(target)`（[scaleModel3d.ts:371](../src/scaleModel3d.ts#L371)）。これは`focusOn()`・`frameAll()`・`focusOnSelection()`から呼ばれる

いずれも`THREE.Vector3.copy()`で**その瞬間の座標値を1回だけコピー**しており、以降その天体を
継続的に追従する仕組みはない。天体の位置が固定だった頃（issue #004以前）はこれで問題なかったが、
今は天体が動き続けるため、一度フォーカスした後に時間を進める（特に月/年モードで再生する）と、
カメラは天体が「いた場所」を見続けたままになり、天体自体は視界からどんどんずれていく。

## 具体的に起きる問題

1. 地球にフォーカスした状態で月/年モードを再生すると、地球は公転で動いていくのに、カメラの
   注視点は動かないため、地球が画面からフレームアウトしていく
2. 地球・月のペアにフォーカスした場合も同様。さらにこちらは、月が地球を約27日で1周するため、
   ペアの中点自体も時間とともに動く
3. `frameAll()`（🏠ボタン）で全天体を収めた直後に時間を進めても、後から天体同士の位置関係が
   変わるため、「全天体が収まっている」保証はその瞬間だけのものになる

## ユーザー提案の方針

注視点を「固定された1つの座標」ではなく、「モデル（フォーカス中の天体）の位置に追従する」
ルールに変更する。

## 合意した方針

**追従は「選択状態」に紐づける。** 新しい状態(`focusedTarget`等)を別に持たず、既存の選択状態
（issue #002の`this.selected: Set<BodyKey>`）をそのまま追従対象として使う。

- 地球を選択 → 地球（の現在位置）に追従。月を選択 → 月に追従。複数選択 → その中心点に追従
- 選択が空（何もない場所をタップして解除）→ 追従も自動的に終わる。選択状態から導出する
  だけなので、専用の解除ロジックは不要（論点4はこれで解決）
- 追従は**注視点だけでなくカメラ位置も同じ移動量(delta)だけ動かす「平行移動」**にする
  （注視点だけ動かしてカメラ位置を動かさないと、距離・見る角度が意図せず変わってしまうため）。
  距離・角度は今ユーザーが設定している状態をそのまま維持する
- 手動操作との関係（論点2）: OrbitControlsは回転・ズームでは注視点を動かさず、パンだけが
  注視点を動かす。毎フレーム注視点を選択中の天体の現在位置に合わせ続けることで、回転・ズームは
  今まで通り自由に効く一方、パンは実質無効化される（次フレームで追従により上書きされるため）。
  追従解除の特別な検知ロジックは不要で、選択に紐づけるだけで自然にこうなる
- 距離の再フィット（論点3の残り）は毎フレーム行わない（常時ズームし続けると酔いやすいため）。
  距離を「ちょうど収まる」状態に再計算するのは、今まで通り明示的な操作（天体の再タップ/Enter/F
  キーでのフォーカス）の時だけ

## 実装方針（概要）

毎フレーム（`syncSceneToOrbitalState()`等、天体の位置更新後）:
1. `this.selected`が空でなければ、選択中の天体（複数なら中心点）の現在座標を計算
2. 前フレームでの同じ計算結果との差分(delta)を求める
3. `controls.target`と`camera.position`の両方に同じdeltaを加算する（平行移動）
4. 選択が変わった（新規選択・解除）直後は、deltaの基準点をリセットする（前回値が無い/選択対象が
   変わった場合はdelta=0として、いきなり大きくジャンプしないようにする）

## 次にやること

上記方針で実装する。
