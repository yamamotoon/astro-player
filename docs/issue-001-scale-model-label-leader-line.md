# Issue #001: スケールモデル: ラベル引き出し線の見直し

対象: [src/scaleModel3d.ts](../src/scaleModel3d.ts) の `updateLabels()` メソッド
（このファイル内の行番号は2026-08-02時点のもの。実装前に現物と照合すること）

## ゴール（不変）

**メイン**: 「天体の外周〜ラベルの外周」の間隔（＝引き出し線の長さ）が長すぎないように
する。特に天体が小さく画面に映っているとき、間隔が天体のレンダリングサイズに対して
不釣り合いに長く見えてはいけない。そのため、この間隔を独立した小さい固定ピクセル値で
直接コントロールできるようにする。

**副次的な効果**: 上記を満たすと、結果として引き出し線が天体本体の絵にもラベルの文字にも
重ならなくなる（重なり自体は今回、不具合として個別に訴えられているものではない）。

## 現状（ゴールとのギャップ）

今のコードは「天体の中心」〜「ラベルの中心」の距離を線で結んでいるだけで、その間隔は
`labelRadius`（ラベルの箱の対角半径。画面上で40〜50px相当の大きな値）にほぼ支配されている。
天体が小さく映っているときは、この`labelRadius`がそのまま線の長さになるため、天体の
レンダリングサイズに対して線が不釣り合いに長く見える。間隔を独立して小さい値に
コントロールする手段がどこにもない、というのが今のギャップ。

## 調査結果（現状のコードの詳細）

天体（太陽・地球・月）の名前ラベルは、天体本体と重ならないよう画面上の位置を
毎フレーム自動調整している。その調整には2段階の「押し出し」処理がある。

- 511-518行目 `overlapOf()`: 2つの円が重なっていたら、重ならなくなる方向・量を返す関数
- 521-530行目: **ラベル同士**の重なりを押し出して解消
- 532-540行目: **ラベルと天体本体（球）**の重なりを押し出して解消
- 543-554行目: 上記で決まったラベル位置を実際に描画し、天体本体の中心からラベル位置まで
  線（引き出し線）を1本引く

天体本体との押し出し量は次の式（535行目 `overlapOf(sphere.x, sphere.y, sphere.r, label.x, label.y, labelRadius)`）で決まる。

```
押し出し後の距離（天体中心 → ラベル中心） = sphere.r + labelRadius
```

- `sphere.r`（507行目）= 天体の見た目の半径。`天体の実半径 / カメラからの距離`。ズームで変わる
- `labelRadius`（487行目）= ラベル文字の見た目の半径。`LABEL_HEIGHT_FRACTION`定数(460行目, 0.035)
  から算出。天体やズームに関係なく一定

そして引き出し線（551-552行目）は、天体本体の中心座標とラベルの中心座標をそのまま結んでいる。

```
現状:  [天体中心]<--sphere.r-->|外周|<--labelRadius-->[ラベル中心]
       引き出し線は [天体中心] から [ラベル中心] まで一直線
       → 天体本体の絵にもラベルの文字にも線が重なって描かれる
```

この2つの値（`sphere.r`・`labelRadius`）はそれぞれ別の目的（天体本体との重なり判定、
ラベル文字の表示サイズ）のためのものであり、「外周間の間隔をいくつにするか」を指定する
変数がどこにもない。これが「調査結果」であり、ゴールとのギャップの技術的な原因。

補足: 天体の中心からラベルまでの距離がズーム操作で変わること自体は問題にしていない。
天体の外周（`sphere.r`）が広がればその分中心からの距離が伸びるのは当然の挙動であり対象外。
問題にしているのは、外周同士の間隔を直接コントロールする手段がないことだけ。

## 修正プラン（調査結果に基づく）

### 要件

1. 天体の外周〜ラベルの外周の間隔を、独立した**固定ピクセル値の定数**として新設する
   （定数名: `LABEL_GAP_PX`、初期値: **10px**。値が気に入らなければこの数値だけ変更すればよい）。
   この値は`sphere.r`にも`labelRadius`にも依存せず、天体の見た目のサイズやズーム操作で変化しない
2. 引き出し線は天体本体の絵にもラベルの文字にも重ならない（外周間の隙間だけを埋める）
3. ラベル同士は重ねない（521-530行目の処理は変更しない）
4. ラベル文字自体の見た目のサイズ（`LABEL_HEIGHT_FRACTION`まわり、460・485-487行目）は変更しない
5. 引き出し線の不透明度を下げる（429行目 現状0.55 → 0.25）
6. 引き出し線の色を天体ごとの色（172-174行目で個別指定）ではなく、単色の控えめな色に統一する
   （例: `#8899bb`）

### 実装方針

```
変更後: [天体中心]<--sphere.r-->|外周|<--GAP_PX-->|ラベル外周|<--labelRadius-->[ラベル中心]
        引き出し線は「外周」〜「ラベル外周」の間、つまりGAP_PXの区間だけを描く
```

#### 1. 定数を追加(460行目付近)

```ts
private static readonly LABEL_GAP_PX = 10
```

#### 2. ピクセル→tan空間の変換値を用意（`updateLabels()`冒頭、487行目の後）

```ts
const canvasHeightPx = this.renderer.domElement.clientHeight
const gapTan = ScaleModel3D.LABEL_GAP_PX * 2 * Math.tan(fovVRad / 2) / canvasHeightPx
```

#### 3. ラベルと天体本体の押し出し量にGAPを追加（535行目）

**ここが要注意点。** 線の描き方だけを変えても、ラベルの実際の位置（衝突判定の結果）が
天体本体にぴったり接したままだと、外周間の隙間は実質ゼロのままで、線の終点がラベルの
中に食い込んでしまう（要件2違反）。ラベルを押し出す距離そのものに`gapTan`を足す必要がある。

```ts
// 変更前
const hit = overlapOf(sphere.x, sphere.y, sphere.r, label.x, label.y, labelRadius)
// 変更後
const hit = overlapOf(sphere.x, sphere.y, sphere.r, label.x, label.y, labelRadius + gapTan)
```

（521-530行目のラベル同士の押し出しは`labelRadius`のまま変更しない＝要件3）

#### 4. 引き出し線を「外周〜ラベル外周」だけに変更（543-554行目）

```ts
for (let i = 0; i < labels.length; i++) {
  const s = labels[i]
  const sphere = spheres[i] // labelsとspheresは同じ順番（太陽・地球・月）

  // ラベル中心（ワールド座標）: 計算方法は変更なし
  s.sprite.position.copy(s.bodyPos)
    .addScaledVector(right, (s.x - s.baseX) * s.depth)
    .addScaledVector(up, (s.y - s.baseY) * s.depth)

  // 天体中心→ラベル中心の方向（tan空間）
  const dx = s.x - s.baseX, dy = s.y - s.baseY
  const dist = Math.hypot(dx, dy)
  const ux = dist > 1e-6 ? dx / dist : 0
  const uy = dist > 1e-6 ? dy / dist : 1

  // 線の始点=天体の外周上の点、終点=ラベルの外周上の点（どちらもtan空間で計算）
  const startX = s.baseX + ux * sphere.r
  const startY = s.baseY + uy * sphere.r
  const endX = s.x - ux * labelRadius
  const endY = s.y - uy * labelRadius

  const toWorld = (tx: number, ty: number) =>
    s.bodyPos.clone()
      .addScaledVector(right, (tx - s.baseX) * s.depth)
      .addScaledVector(up, (ty - s.baseY) * s.depth)

  const lineStart = toWorld(startX, startY)
  const lineEnd = toWorld(endX, endY)

  const posAttr = s.leader.geometry.attributes.position as THREE.BufferAttribute
  posAttr.setXYZ(0, lineStart.x, lineStart.y, lineStart.z)
  posAttr.setXYZ(1, lineEnd.x, lineEnd.y, lineEnd.z)
  posAttr.needsUpdate = true
}
```

手順3でラベルの押し出し量に`gapTan`を足しているため、通常時（他のラベル/天体との
干渉がない場合）はこの線の長さが正確に`LABEL_GAP_PX`になる。他のラベルや天体との
衝突でラベルがさらに押し出された場合は、その分だけ線が長くなる（隙間が広がるだけで、
重なりは発生しない）。

#### 5. 引き出し線の見た目（429行目 `makeLeaderLine`、172-174行目の呼び出し部）

- `opacity: 0.55` → `0.25`
- `makeLeaderLine('#ffee44')` / `'#8fc0ff'` / `'#ccd4ee'`（天体ごとに異なる色）
  → 3箇所とも同じ色に統一する（例: `makeLeaderLine('#8899bb')`）

## 実装中に追加で見つかった問題（当初の修正プランには含まれていなかったもの）

上記の修正プランを実装して目視確認したところ、線が天体の絵に重なって見える不具合が
残っていた。原因を調査した結果、当初の実装方針だけでは不十分で、以下3つの追加の
計算誤りが見つかった。**この3つも修正済み。**

### 追加バグA: 引き出し線の始点を計算するコードが、天体の輪郭の位置を実際より内側に見積もっていた

- **現象**: 天体にズームインすると、引き出し線（および始点マーカー）が天体の絵に
  重なって見える。ズームするほど重なりが大きくなる。
- **原因**: 天体本体の3D描画（`THREE.SphereGeometry`をThree.jsの標準の仕組みで描画している
  部分）にバグはなく、天体の輪郭（見た目）自体は最初から正しく表示されている。バグは
  `updateLabels()`内で「その正しく描画されている輪郭が、画面上のどの座標に来るか」を
  別途計算していたコードの方にあり、そこが実際の輪郭より内側の座標を算出してしまっていた。
  具体的には次の通り。カメラから天体中心までの距離を`D`、天体の実半径を`R`とすると、
  コードの`sphere.r = R/D`。画面上の位置は「横方向のズレ量 ÷ 奥行き」の比（tan空間の値）
  で決まる。

  実際に画面上で見える天体の輪郭は、カメラから天体への接線が触れる点。
  「カメラ・天体中心・接点」でできる直角三角形（接点で直角）から、輪郭の視角度`φ`は
  `sinφ = R/D`という関係になり、輪郭が画面上に現れるtan空間の値は`tanφ`。

  旧コードは輪郭上の点を「天体中心と同じ奥行きのまま、`sphere.r`(=R/D)だけ横にずらした点」
  として計算していた。この点のtan空間の値は`R/D = sinφ`。

  `φ`が0°より大きい限り常に`tanφ > sinφ`（`cosφ`は1より小さいため）。つまり旧コードの点
  (`sinφ`)は、常に正しい輪郭(`tanφ`)より画面中心寄り＝天体の絵の内側に来てしまう。
  `φ`が大きいほど（ズームして天体が画面に大きく映るほど）差が拡大し、天体にフォーカスして
  ズームした状態では画面上で10px前後の誤差になっていた。
- **修正方法**: `sphereEdgeTan(r) = r / √(1 - r²)`（θ=輪郭の視半径、sinθ=rとなる
  直角三角形から導出）で正しい輪郭位置に補正した（`updateLabels()`内、`sphereEdgeTan`関数）。
- **修正確認方法**: ブラウザで天体（特に地球・月）をクリックしてフォーカスし、大きく
  ズームインした状態で、引き出し線・始点マーカーが天体の絵にかぶらず、輪郭のすぐ外側から
  始まっていることを目視確認する。

### 追加バグB: ラベルを押し出す距離が、方向によらず一律「対角円の半径」を使っていた

- **現象**: マゼンタマーカー（終点側の目印）からラベルの文字までの間隔が、指定した
  `DEBUG_MAGENTA_TO_LABEL_PX`（10px）通りになっておらず、実際にはもっと離れて見える。
- **原因**: ラベルは横長（幅が高さの4倍、`makeLabel()`のcanvasサイズ256×64に由来）の
  長方形。天体からラベルを押し出す距離の計算で、この長方形の対角線方向の半径
  （`labelRadius = hypot(labelHalfW, labelHalfH)`、四隅を含む円の半径）を、実際に
  押し出される方向（多くの場合ほぼ真上）に関係なく一律に使っていた。真上方向での本来の
  「中心から辺までの距離」は`labelHalfH`であり、`labelRadius`の約1/4しかない。結果、
  ラベルが必要以上に遠くへ（本来の想定よりさらに`labelRadius-labelHalfH`分ほど余計に）
  押し出されていた。
- **修正方法**: 押し出す方向(ux, uy)ごとに長方形の実際の辺までの距離を返す
  `labelEdgeDistTo(ux, uy)`に置き換え、天体とラベルの押し出し判定を専用の
  `overlapSphereLabel()`に分離した（ラベル同士の押し出しは従来通り`labelRadius`のまま。
  要件3を維持）。
- **修正確認方法**: ブラウザでマゼンタマーカーからラベルの文字までの間隔が、指定した
  `DEBUG_MAGENTA_TO_LABEL_PX`（10px）とおおよそ一致していることを目視確認する。
  （注: `DEBUG_MAGENTA_TO_LABEL_PX`はデバッグ用の一時的な定数名。現在は本番仕様の
  `LINE_TO_LABEL_PX`に置き換わっている。詳細は後述「要件変更（最終仕様）」参照）

### 追加バグC: 天体に極端にズームインすると`sphereEdgeTan`が発散し、ラベルが画面外に消える

- **現象**: 天体（特に地球・太陽など月より半径が大きい天体）にズームインを続けると、
  ある距離を超えたところでラベルが見えなくなる。
- **原因**: 追加バグAの修正で導入した`sphereEdgeTan(r) = r / √(1 - r²)`は、`r`が1に
  近づく（＝カメラが天体の半径より近づく）ほど値が急激に大きくなり、`r`が1以上になると
  数式が破綻する（√の中身が0以下になる）。このアプリのズームの下限
  （`OrbitControls.minDistance = MOON_R * 3`）は天体ごとに調整されておらず固定値のため、
  月より半径が大きい天体（地球は月の約3.67倍、太陽は約400倍）では、ズームでカメラが
  その天体の半径よりも近づける状態になり得る。その場合`r`が1を超え、`sphereEdgeTan`が
  異常な巨大値を返し、ラベルの位置が画面外の遠方まで押し出されてしまっていた。
- **修正方法**: `sphereEdgeTan`内で`r`を`0.98`を上限にクランプしてから計算するようにした
  （`updateLabels()`内、`sphereEdgeTan`関数）。
- **修正確認方法**: ブラウザで地球・太陽など大きめの天体にフォーカスし、ズームの下限まで
  近づけても、ラベルが画面内に表示され続けることを目視確認する。

### 備考（未着手・要判断）

ラベルの当たり判定に使っている矩形（256×64px相当）は背景が透明で、実際に見えているのは
中の文字（グリフ）だけ。透明な余白部分まで「ラベルの範囲」として計算に使っているため、
計算上の間隔と目視で感じる間隔がわずかにズレる可能性がある
（`ctx.measureText()`での実測に置き換えれば解消できるが、要件4「ラベル自体の見た目の
サイズは変更しない」の範囲を超えるため未実施。目視確認の結果、現状で許容範囲と判断された）。

## 要件変更（最終仕様）: 単一のLABEL_GAP_PXから3区間構成へ

デバッグ用に「モデル〜緑〜マゼンタ〜ラベル」の3区間マーカーを一時的に入れて目視確認した
ところ、この3区間構成そのものを本番の仕様として採用することになった。**当初の要件1
（`LABEL_GAP_PX`単一の値で、線が天体の外周に直接触れる）は、この節の内容に置き換え。**

天体の外周〜ラベルの外周を、次の3区間の画面ピクセル値で構成する（天体の見た目のサイズや
ズームに関係なく常にこの値を保つ。数値を変えるだけで間隔を調整できる）。

```
天体の外周(sphereEdgeTan) → MODEL_TO_LINE_PX(10px) → 引き出し線の始点
  → LINE_LENGTH_PX(20px) → 引き出し線の終点
  → LINE_TO_LABEL_PX(10px) → ラベルの外周
```

引き出し線は「引き出し線の始点〜終点」の20px区間だけを描画する。天体〜線の10px、
線〜ラベルの10pxは、どちらも何も描画しない空白区間で、これにより線が天体本体にも
ラベルにも触れない（デバッグ時に使っていた緑・マゼンタのマーカーメッシュ
`debugLineMarkers`は目視確認用だったため、確認完了後に削除済み。現在のコードには残っていない）。

`updateLabels()`内の対応する定数・変数名: `MODEL_TO_LINE_PX` / `LINE_LENGTH_PX` /
`LINE_TO_LABEL_PX`（460行目付近）、`modelToLineTan` / `lineLengthTan` / `lineToLabelTan`
（tan空間に変換した値）。ラベルの押し出し量には3区間の合計(`totalGapTan`)を使う。

遠近法補正(`sphereEdgeTan`)と方向ごとのラベル辺距離(`labelEdgeDistTo`)の修正
（追加バグA・B）は、この構成変更とは別の、独立したバグ修正としてそのまま残る。

## 動作確認方法

`npm run dev` で起動し、スケールモデル画面で以下を目視確認する。

- 天体にズームインしても引き出し線が天体の絵の上に乗らないこと ✅確認済み
- 引き出し線がラベルの文字に重ならないこと ✅確認済み
- 天体の外周〜引き出し線の始点の間に、10px相当の隙間があること
- 引き出し線自体の長さが20px相当であること
- 引き出し線の終点〜ラベルの外周の間に、10px相当の隙間があること
- 極端にズームインしても（`sphere.r`が1に近づいても）ラベルが画面外に飛ばず表示され続けること
- 全体表示（Home）で地球・月が近接しても、2本の引き出し線が1本のようにつながって
  見えないこと（各線が短く、外周同士だけを結んでいること）
- ラベル同士は今まで通り重ならないこと
