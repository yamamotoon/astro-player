# スケールモデル カメラ操作 仕様（合意版・未実装）

議論の末に確定した仕様。このファイルの内容はまだコードに反映されていない。
実装時はこのファイルを一次情報として進める。

## 用語（誤解を避けるため統一する）

- **選択**: 天体をアプリ内部の状態としてマークすること。ラベル強調＋天体への軽い発光で見た目に示す。
  **カメラは一切動かない**。
- **フォーカス**: 選択されている天体（複数可）がちょうど画面に収まるよう、カメラの**位置（注視点からの距離）を移動**させること。
  FOV（画角、`camera.fov`）は50度固定のまま変更しない。既存の`moveCameraTo()`/`frameDistance()`の
  仕組み（距離のみを動かす、ドリー方式）をそのまま使う。「ズーム」という言葉は距離移動かFOV変化か
  曖昧になるため使わない。

## 現状の課題（見直しの動機）

1. クリックが選択とフォーカスを兼ねており、常に大きなカメラ移動を伴う。「軽く見るだけ」ができない
2. ブラウザの`click`イベントはドラッグ後のmouseupでも発火するため、軌道回転の指を離した場所が
   たまたま天体の上だと意図せずフォーカスが起きる
3. 天体（特に月）は縮尺の都合でほぼ1pxの点になる場面が多く、球体メッシュへの直接レイキャストだけでは
   実用的にクリック/タップできない
4. 複数天体をまとめて見たい（例: 地球と月の関係）場面が実際の主要な使い方だが、既存の矩形選択モードは
   ⬚ボタンでの明示的なモード切り替えを要求し、一手間かかる

## 確定仕様

### カメラの基本操作（変更なし）

| 操作 | PC | モバイル |
|---|---|---|
| 軌道回転 | 左ドラッグ | 1本指ドラッグ |
| パン | 右ドラッグ | 2本指ドラッグ |
| 距離移動（手動） | スクロール | ピンチ |
| 全天体をフォーカス | Home キー／🏠ボタン | 🏠ボタン |

### 選択・フォーカス（新規）

天体1つに対する操作ルールは1つだけ:

- **未選択の天体を押す（クリック/タップ） → 選択に追加**（前の選択を置き換えない。複数回押せば複数選択できる）
- **既に選択されている天体を押す → 選択されている天体すべてにフォーカス**（カメラが距離を詰める）
- **何もない場所を押す → 選択をすべて解除**（カメラは動かさない）
- フォーカス後も選択状態は保持する（自動では解除しない。実際に使ってみて違和感があれば調整する）

PCのみの補助ショートカット: 選択中に Enter／F キーでフォーカス（クリックと同じ効果、任意）。

矩形選択モード（⬚ボタン）は**廃止**する。天体が3つしかなく、かつ下記の当たり判定改善により
1つずつ押して選択を積み上げる方式で十分カバーできるため。

### 当たり判定

天体を押した判定は、次の**両方をOR**で見る:

1. 天体の球体メッシュへの通常のレイキャスト（ズームインして大きく見えている時に有効）
2. 天体の**ラベル**の表示範囲（常に画面上一定サイズを保つよう既存実装で制御されているため、
   天体がどれだけ縮んでもラベルは一定の大きさの的になる。ズームアウトして点のようになっている時に有効）

いずれかにヒットすれば、その天体に対する押下として扱う。

### 実装上の注意

- クリック/タップ判定は、ブラウザの`click`イベントではなく`pointerdown`→`pointerup`の位置・時間差を
  自前で判定する（ドラッグ末尾での誤発火を防ぐため）
- 「フォーカス」は既存の`moveCameraTo()`/`frameDistanceForBodies()`をそのまま使う。選択が複数の場合は
  既存の`frameDistanceForBodies()`（複数天体対応）を、単一の場合は`frameDistance()`を使う想定

## 想定シナリオ（設計の検証に使ったもの）

「全天体表示から、気になるペアだけ拡大したい」:
1. 🏠で全天体表示
2. 地球を選択
3. 月を選択に追加（地球・月は近接して小さく見えるが、ラベル同士は既存の衝突回避ロジックで
   重ならないよう離れるため、それぞれ個別に押せる）
4. どちらかを再度押す → 地球・月のペアがちょうど収まる距離までカメラが移動
