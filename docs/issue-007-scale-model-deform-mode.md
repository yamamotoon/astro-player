# Issue #007: スケールモデルのデフォルメ表示モード

## 状態

**実装済み。ブラウザでの動作確認待ち（過去の試行錯誤は`backup/deform-distance-scale-wip`ブランチに退避済み）**

## 背景・課題

スケールモデルは実際の距離・大きさの比率をそのまま再現している（月半径=1のとき、地球半径≒3.67・
太陽半径≒400.7・地球〜月距離≒221.3・地球〜太陽距離≒86,125）。この比率は正確だが、極端すぎて
「フォーカス」で1天体ずつ見ることはできても、**複数の天体を同じ画面内で、動きが分かる状態で
見ることが難しい**。

具体的には:

- 太陽と地球の半径比は約109:1で、これは実寸でも変わらない（拡大しても比は変わらない）
- 地球〜太陽の距離(≒86,125)は太陽自身の半径(≒400.7)の200倍以上あるため、両方を画面に収めようと
  すると地球は事実上の点になる
- 地球〜月の距離(≒221.3)は、地球半径＋月半径(≒4.67)の約47倍しかなく、地球を「モデルとして
  認識できる」大きさまで拡大しようとすると、月との間にほとんど余白がない

過去に「天体サイズだけを拡大する」「距離だけを縮める」を別々の場当たり的な操作として試したが、
この2つは独立ではなく、組み合わせ次第で天体同士が重なってしまうことが分かった
（`backup/deform-distance-scale-wip`参照）。設計を整理せずに進めた結果、同じルール
（例:「太陽はデフォルメ対象外」）がコードの複数箇所に重複するなど、保守しづらい状態になった。

## 解決したい課題（要件）

実装方法(ボタン/スライダー等)やアルゴリズムの前に、まず「何が満たされていれば良いか」を明確にする。

1. **実寸表示を基本とし、それを損なわず切り替えられること。** 正確な比率を見せるのがこのアプリの
   本来の価値なので、デフォルメはあくまで補助的な別モードであるべき
2. **デフォルメ時、太陽・地球・月それぞれが「モデルとして認識できる」大きさで描画されること。**
   点や1〜2pxのドットではなく、球体だと分かる大きさ
3. **デフォルメ時、月の公転運動が画面内で視認できること。** 地球の周りを回っていることが動きとして
   分かる（地球にくっついた点ではなく、軌道を描いて動くのが見える）
4. **デフォルメ時、地球の自転運動が認識できる大きさで描画されること.** テクスチャの模様が回転して
   いるのが分かる程度の画面上のサイズが必要
5. **NG条件: いかなる天体も、他の天体のモデルに埋まってはいけない。** サイズを拡大した結果、
   天体同士の球が交差・重なることがあってはならない（過去の試行で×50デフォルメ時に地球と月が
   重なったのはこのNG条件に抵触する）

## 合意した方針

### 1. 天体の大きさは全部「同じ」にする

太陽・地球・月の相対サイズ比（実際は約109:1）を保ったまま拡大しようとすると、要件2(認識できる
大きさ)と要件5(重ならない)が両立しない組み合わせが必ず出てくる（`backup/deform-distance-scale-wip`
での試行錯誤で判明）。デフォルメモードでは正確な相対サイズを見せることは諦め、**太陽・地球・月を
すべて同じ半径**で描画する。これにより「各天体がモデルとして認識できる」(要件2)は自動的に満たされ、
重なり判定も全ペアで同じ余裕度になり単純化する。

### 2. 距離は「表面間のギャップ」から逆算する（中心間距離を直接指定しない）

中心間距離を基準に「実際の距離の何%」のように決めると、重ならないことを別途チェックする必要が
生じる。代わりに、**表面間のギャップ（半径の倍数）を先に決め、中心間距離 = 半径×2 + ギャップ**
から逆算する。ギャップ ≧ 0 である限り、どのペアも構造的に重なりようがない（要件5を自動的に満たす）。
ギャップの大きさそのものが「衛星の公転運動が画面内で認識できるか」(要件3)を直接コントロールする
パラメータにもなる。

### 3. 距離比は「見やすさ」優先で決めてよい（満ち欠けの精度は無視できるレベル）

月の満ち欠けは月モデルへのライティング（太陽→地球方向を再利用する共用のDirectionalLight）で
表現している。DirectionalLightは距離による減衰が無いため太陽からの距離自体は影響せず、月の公転
角度（`SunCalc`の実測値、距離に関係なく常に正確）が満ち欠けの「形」を決めている。太陽〜地球と
地球〜月の距離比が実際と異なることで生じる誤差は、共用ライティングによる光源方向のわずかな
ズレ（数度程度）にとどまり、月モデル自体もテクスチャなしの単色球体のため視覚的にはほぼ判別できない。
→ 学習目的においては誤差レベルとみなし、距離比は「見やすさ」を優先して決める。

### 4. 具体的な数値（暫定）

検証用に導出した式（半径R、ギャップは半径の倍数で指定）:

```
R = 10                      // 全天体共通の半径（実際の月半径の10倍）
地球〜月距離 = 2R + 3R = 50   // ギャップ = 半径の3倍
太陽〜地球距離 = 2R + 8R = 100 // ギャップ = 半径の8倍（地球〜月よりは離れている、という感覚は残す）
```

この数値で「系全体」表示時の角度比を検証済み: 地球〜月ビューで地球が画面の約17.4%、
太陽〜地球ビューで太陽・地球が約8.7%（実寸モードではどちらも1%未満）。重なりは構造的に発生しない
（ギャップ>0のため）。実装時に見た目を見ながら微調整可能。

### 5. UI

実寸⇔デフォルメの**単純な2状態トグル**にする（連続スライダーやボタン群は撤去）。ユーザーが
重なる組み合わせを作れてしまう余地自体をなくす。
