# Issue #004: スケールモデルを時間と連動させる（自転・公転・シークバー）

## 状態

**Phase 1（コアロジック）・Phase 2（UI）実装・ユーザー確認済み。Phase 3（既存24hシミュレーションのリファクタ）着手中。**

## Phase 1 実装メモ

- `src/playbackController.ts`（新規）: 周期長・実時間換算・再生位置・再生/停止を管理する汎用クラス
- `scaleModel3d.ts`: `computeOrbitalPositions()`で円軌道による地球・月の位置を計算（地球は年内の
  経過日数、月は`SunCalc.getMoonIllumination()`の実測月相を基準）。`syncSceneToOrbitalState()`が
  それをシーンに反映
- **自転バグとその修正**: 初回実装では自転角度を「UTC時刻の端数×2π」という、実際のテクスチャの
  経度と一切対応しない値で計算していたため、日本(135°E)が実際には昼でも画面上は夜になる不具合が
  あった（ユーザー指摘により発覚）。`THREE.SphereGeometry`の実際の頂点式
  (`vertex.x=-r·cosφ, vertex.z=r·sinφ, φ=π+lon`)から経度→ローカル方向を逆算し、UTC時刻から
  「今どの経度が太陽の正面(南中)にあるか」を求めた上で、その経度が実際に太陽方向を向くよう
  自転角度を逆算する方式に修正。`three.js`の実際のVector3/Quaternionクラスを使い、日本の経度で
  UTC0〜21時の8パターンについて昼夜判定が実際のJST時刻と一致することを検証済み
  （日の出/日の入りちょうどの境界2点を除き全て一致）

## Phase 2 実装メモ

`index.html`にスケールモデル専用の時間バー(`#scale-playback`)を追加（日/月/年切り替えボタン・
シークバー・再生/停止ボタン・現在のシミュレーション日時ラベル）。既存の`.playback`/`.play-btn`/
`.seekbar`スタイルを再利用して見た目の統一感を保った。DOM操作・イベント配線は`ScaleModel3D`が
自己完結して行う（`main.ts`は`showScene()`での表示/非表示切り替えのみ）。ユーザーがブラウザで
動作確認済み。

## Phase 3（次にやること）

3D+2D/SKY側の既存24hシミュレーション（`main.ts`の`ANIM_DURATION_MS`/`animStep`/`applySimMinute`）
を、Phase 1で作った`PlaybackController`を使う形にリファクタする。既存動作（シークバー・再生/停止・
リアルタイム追従チェックボックス）を壊さないよう注意する。

## 背景・現状（コードを確認した事実）

- `scaleModel3d.ts`の地球の自転は、実際の日時と無関係に**ページを開いてからの経過時間だけ**で
  回っている（`EARTH_SPIN_RAD_PER_SEC = 2π/24`、`rotateOnWorldAxis(...,  * dt)`）。特定の日時の
  地球の向きを再現する仕組みは無い。
- 太陽・地球・月の**位置**は`SUN_POS`/`EARTH_POS`/`MOON_POS`という固定座標で、公転運動は
  未実装（`CLAUDE.md`にも明記: 「v1では地球・月の配置は簡易的な固定角度（軌道運動は未実装）」）。
- 3D+2D/SKYモードには既に「24時間シミュレーション」がある(`main.ts`の`ANIM_DURATION_MS`/
  `seekbar`/`play-btn`)。`datetimeInput`（日時）1つを基準に、シークバー(0〜1439分、1日分)・
  再生/停止ボタン・「リアルタイム」チェックボックスが1組あり、`update()`が`scene3d`/
  `compass2d`/`arView`へ同じ`date`を配って描画させている。
- ただし`CLAUDE.md`には**「スケールモデルは緯度経度・日時に依存しない独立画面（カメラ操作のみ）
  のため、HUDを使わない」**と明記されている。これは既存の意図的な設計であり、今回の要望は
  この設計を変更することになる。

## 要望（ユーザーからの原文の要約）

1. 地球の自転を、実際の日時と連動させたい（今は日時と無関係に回り続けているだけ）
2. 地球・月・太陽の「位置」も日時と連動させたい（＝公転運動の実装）
3. 画面下部にシークバーまたは再生バーを用意し、時間を操作（スクラブ）・再生・停止できるように
   したい

## 実装にあたって決めておくべき論点（未決定）

### 1. 時計はモード間で共有するか、スケールモデル独自にするか → 決定: 独自
シークバーの起点が常に「現在の実時刻」（論点2参照）であり、3D+2D/SKYの`datetimeInput`
（任意の日時を手動で選べる)とは性質が異なるため、スケールモデル専用の独立した時計・UIとする。
`CLAUDE.md`の「スケールモデルは緯度経度・日時に依存しない独立画面」の記述は、今回の変更に
合わせて更新が必要（日時そのものに依存するようになるため）。

### 2. 「1日」と「1年」で必要な時間スケールが全く違う → 決定: 3段階のモード切り替え

自転(1日)は今の「1秒=1時間、24秒で1日」という換算がある。しかし公転（地球=365日、月=27.3日）
まで同じシークバーで表現しようとすると、「1日分(24秒)」のシークバーでは地球はほぼ動かず
(1/365日分)、公転が見た目に分からない。逆に「1年分」を1本のシークバーにすると、自転が
365回転分になり、日単位の自転は速すぎて見えなくなる。

**合意**: 「1日モード」「1か月モード」「1年モード」の3段階をUIで切り替えられるようにする。

- 1日モード: 地球の自転（昼夜）が主役。月・地球の公転はほぼ動かない（このモードでは元々見せる対象ではない）
- 1か月モード: 月の公転（満ち欠け相当の位置変化）が主役。地球の公転はごく僅かに進む
- 1年モード: 地球の公転が主役。月は十数周分公転する（早回しになる想定）

**合意（シークバーの基準点）**:
- シークバーの起点(0%)は常に「現在の実時刻」
- そこから未来方向に、モードに応じて24時間/1か月/1年分だけ進む（過去方向には遡らない）
- モードを切り替えたら、シークバーは毎回先頭(=現在時刻)にリセットしてよい

**合意（再生時間）**: 日/月/年どのモードも、既存の24hシミュレーションと同じ実時間感覚
（1周期分を再生し切るのにかかる実時間は揃える）で統一する。モードによって「1周期の長さ
（24時間/1か月/1年）」が変わるだけで、体感の再生速度感（実時間としての長さ）は変えない。

### 3. 公転運動の精度 → 決定: 円軌道で簡略化
実際の離心率・ケプラーの法則に基づく楕円軌道までは再現せず、一定速度で回る円軌道として
簡略化する。プロジェクトの他の部分（大陸のイラスト化、v1の固定角度配置）でも「厳密な科学的
正確性より、分かりやすい簡略化」を基本方針にしてきているため、それに合わせた。

### 4. 地軸の傾きの向きも連動させるか → 実装時に確認（ユーザー判断不要の実装詳細）
現状、地軸(`EARTH_AXIS`)は常にワールド座標で固定方向。実際の地球は「地軸の向きは1年を通じて
（ほぼ）固定だが、太陽との相対角度が公転によって変わることで季節が生まれる」。公転を実装する
際は地軸の向きは固定のまま地球の位置だけ動かせば、この関係は自動的に正しくなるはずなので、
実装時にそうなっているか確認する。

### 5. 「今の実際の日時」に紐づけるか、任意の周期的アニメーションとして扱うか → 決定: 実際の日時に紐づける
論点2の合意の通り、シークバーの起点は常に「現在の実時刻」。停止中の基準点も「今の位置」。

### 6. UIの置き場所 → 決定: 専用UIを新設。ただしロジックは共通化・見た目は統一感を持たせる
既存の`#scene-playback`とは別に、スケールモデル画面下部に専用のUI（日/月/年切り替え＋
シークバー＋再生/停止ボタン）を新設する。ただし:
- ロジック（シークバーの位置↔経過時間の変換、再生/停止のRAFループ管理）は、既存の24h
  シミュレーション（`main.ts`の`animStep`/`applySimMinute`相当）と共通化できる形に切り出す
  （周期の長さ・実時間換算・現在値を渡せる小さいコントローラー/関数にする）
- 見た目（CSS）は既存の`.playback`バーのスタイルに合わせ、UIの統一感を保つ
- 既存の3D+2D/SKY側の24hシミュレーションを今回のリファクタで壊さないよう注意する
