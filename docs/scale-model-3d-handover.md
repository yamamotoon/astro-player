# スケールモデル機能

ブランチ: `feature/scale-model-3d`

## 目的

地球・月・太陽（実験的に水星・金星・火星も）の**距離と大きさを実際の比率で正確に**再現する3Dモデル。
メニューから3つの入口があり、同じ`ScaleModel3D`クラス・同じDOM（`#scene-scale`/`#scale-playback`/
`#canvas-scale`）を、入る時に渡す`ScaleModelConfig`（表示モード・デフォルメ初期値・初期ターゲット・
内惑星表示可否）だけを変えて使い回す。同時に複数インスタンスは存在させない（切り替えるたびに
`dispose()`してから作り直す）。

- **スケール**（既存）: 太陽・地球・月、日/月/年モード全部、実寸スタート
- **地球の公転ビューア**: 太陽・地球・月・水星・金星・火星、月/年モードのみ、デフォルメスタート、
  太陽が注視点
- **地球の自転ビューア**: 太陽・地球・月、日/月モードのみ、デフォルメスタート、地球が注視点

月半径=1を基準単位とする（月半径1のとき: 地球半径≒3.67・太陽半径≒400.7・地球〜月距離≒221.3・
地球〜太陽距離≒86,125）。星座・恒星はスコープ外。

## 単位系・座標変換

物理計算（`computeOrbitalPositions()`・日付/角度/方向ベクトルの計算・物理定数）は`src/orbitalMath.ts`
に分離している（DOM・Three.jsのシーン/カメラに一切依存しない純粋モジュール。`astroCalc.ts`と
`scene3d.ts`の関係と同じ構図）。`scaleModel3d.ts`はThree.jsのメッシュ生成・カメラ操作・DOM配線を担当する。

実際の物理値(km)から比率を算出する（ハードコードしない）。距離比が非常に大きいため、月規模〜太陽規模
の行き来はOrbitControlsのズームで行う（`minDistance`/`maxDistance`を広く設定）。

太陽を原点・Y軸を公転面(黄道面=XZ平面)の法線とする独自座標系を使う（3D+2D/SKYモードの観測者中心
Alt/Az座標とは別物）。公転軌道はcosθ・-sinθ（+Y=北から見て反時計回り。実際の公転方向と一致）で
計算する。地軸傾斜（-23.44度。符号は季節と対応するよう検証済み）・月の潮汐固定・緯度経度→地表方向の
変換（`localDirForLatLon()`）も`orbitalMath.ts`にある。

## 実装済みの機能

- 太陽・地球・月（+実験的に水星・金星・火星）の円軌道による公転運動（実際の日時に連動）
- OrbitControlsでドラッグ回転・ズーム
- 天体クリック/タップで対象(`targetBody`)を切り替え、「フォーカス」「系全体」ボタンでカメラ移動
- Homeキー／🏠ボタンで全天体が収まる位置へ
- 地球: NASA実写(LROC)ベースのテクスチャ＋`MeshLambertMaterial`、実際の地軸傾斜(23.44度)・自転
  （UTC時刻から南中経度を逆算、日本(135°E)など実在の経度の昼夜が実際の時刻と一致）
- 月: 潮汐固定（常に同じ面を地球に向ける）、軌道面の傾き(5.14度)、実際の月相(SunCalc)に基づく満ち欠け
- 東京の位置マーカー（円錐。地球メッシュの子で自転・公転・デフォルメに自動追従）
- デフォルメ表示モード（issue #007）: 太陽・地球・月（水星等表示中はそれも）を同じ見た目の半径にし、
  距離もギャップ計算で重ならないよう配置。実寸⇔デフォルメをボタンで切替、`ScaleModelConfig`で初期値指定可
- 時間バー: 日/月/年モード切替、シークバー、再生/停止、常時多段ステップボタン（時/日/月。シーク範囲に
  縛られず時刻そのものを移動する）
- 天体名ラベル: 画面上で常に一定サイズ・常に手前表示、引き出し線、ラベル同士／天体本体との重なりを
  毎フレーム衝突判定で解消（`activeBodyKeys()`で表示中の天体だけを対象にする）
- カメラの「向き」だけをメインカメラと同期するミニ座標軸ギズモ
- モード切替時の`dispose()`: 全リスナー解除＋Three.jsのgeometry/material/texture/rendererの解放

## 実装中に見つけて直した不具合（今後の類似実装での注意点）

1. **単一天体フォーカスがアスペクト比を見ていなかった**: 縦方向FOVだけで距離を計算しており、縦長画面で横にはみ出す不具合があった。縦横両方のFOVを見て厳しい方を採用するよう修正。
2. **複数天体フレーミングで奥行き差を無視していた**: 中心より手前にある天体は同じ横ズレでも遠近法で画面上大きくズレて見えるのに、それを計算に入れておらず画面に収まらないことがあった。
3. **`.fullscreen-btn`クラスの誤爆**: 見た目を揃えるためだけに独自ボタンへ`fullscreen-btn`クラスを付けたところ、`main.ts`の汎用フルスクリーン配線（クラス名だけで選択）が誤って反応した。`data-target`属性の有無でセレクタを絞って対処。
4. **非表示中に生成したcanvasがゼロサイズになる**: `display:none`の親を持つ要素は`clientWidth/clientHeight`が0になる。固定サイズの要素はレイアウト依存の値を使わず、HTML属性の固定値を直接使うようにした。
5. **OrbitControlsの「ダンピングを一旦切って同期」処理が逆効果だった**: 残存回転量(`sphericalDelta`)を抑えるつもりが、`enableDamping=false`にすると全量が一気に適用される仕様（ソース確認済み）で、直前にドラッグ操作していると意図しない回転が起きた。`camera.lookAt()`を直接呼ぶだけのシンプルな実装に変更。
6. **ラベル位置決めロジックの試行錯誤**: 天体ごとの固定オフセット方向 → グローバル重心基準の外向きオフセット、といずれも不十分だった（後者は2天体選択時に破綻し、近接する2天体が同じ方向に押されて重なる問題を解決できない）。最終的に、ラベルは天体の実座標を起点とし、ラベル同士・ラベルと天体本体の重なりをペアごとの円形衝突判定で毎フレーム解消する方式に落ち着いた。判定は「視線からの角度のtan」空間で行い、距離による遠近を正しく考慮している。
7. **地球・月の公転方向が実際と逆（時計回り）だった**: `(cosθ, sinθ)`という素朴な式は+Y(北)から見て時計回りになる。数値検証で確認し、Z成分の符号を反転して反時計回りに修正。
8. **地軸傾斜の向きが季節と逆だった**: `EARTH_AXIS`の回転符号が実際の季節（6月に北極が太陽側を向くべき）と逆になっていた。dayOfYearFraction()の公転角度の基準との組み合わせで初めて決まるため、数値検証（6/21・12/21で北極と太陽方向の内積を確認）で修正。
9. **デフォルメ起動時にメッシュのscaleが適用されず、カメラが埋まる**: デフォルメ⇔実寸の切替処理(`toggleDeformMode()`)にしかメッシュscale変更が書かれておらず、`ScaleModelConfig.deformDefault=true`でいきなりデフォルメ起動すると、位置はデフォルメ距離なのにメッシュは実寸サイズのままになっていた。`applyDeformVisuals()`に切り出し、起動時にも呼ぶよう修正。
10. **`hidden`属性が`display:flex`指定のクラスに上書きされる**: `.scale-step-group{display:flex}`というCSSクラスと`hidden`属性を同じ要素に使うと、author CSSがUA標準の`[hidden]{display:none}`を上書きしてしまい非表示にならない（ステップ再生A/B比較の実装時に発覚。`.scale-step-group[hidden]{display:none}`を追加して対処）。
