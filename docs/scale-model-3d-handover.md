# スケールモデル機能

ブランチ: `feature/scale-model-3d`

## 目的

地球・月・太陽の**距離と大きさを実際の比率で正確に**再現する新モード「スケールモデル」を、
既存の3D+2D／SKYモードとは別モードとしてメニューに追加する。既存モードは比較用に無変更のまま残す。
月半径=1を基準単位とする（月半径1のとき: 地球半径≒3.67・太陽半径≒400.7・地球〜月距離≒221.3・
地球〜太陽距離≒86,125）。見やすさのための誇張はせず、実際の比率をそのまま使う方針。星座・恒星は
今回のスコープ外。

## 単位系・座標変換

`scaleModel3d.ts`は月半径=1になるよう、実際の物理値(km)から比率を算出する（ハードコードしない）。
月半径1のとき、地球半径≒3.67・太陽半径≒400.7・地球〜月距離≒221.3・地球〜太陽距離≒86,125。
距離比が非常に大きいため、月規模〜太陽規模の行き来はOrbitControlsのズームで行う
（`minDistance`/`maxDistance`を広く設定）。

太陽を原点・Y軸を公転面(黄道面=XZ平面)の法線とする独自座標系を使う（3D+2D/SKYモードの
観測者中心Alt/Az座標とは別物）。公転軌道はcosθ・-sinθ（+Y=北から見て反時計回り）で計算する。
地軸傾斜・月の潮汐固定・緯度経度→地表方向の変換もこのファイル内で完結する
（`EARTH_AXIS`/`localDirForLatLon()`等）。

## 実装済みの機能

- 太陽を原点、地球+X方向、月は地球から+Z方向の固定配置（**v1は軌道運動なし**、静的配置）
- OrbitControlsでドラッグ回転・ズーム
- 天体クリックでフォーカス（該当天体が画面に収まる距離まで、視線角度は変えずに移動）
- Homeキー／🏠ボタンで全天体が収まる位置へ
- 矩形選択モード（⬚ボタンでトグル）: ドラッグで囲んだ複数天体をまとめてフォーカス
- 地球: イラスト調テクスチャ（Canvas生成）＋`MeshLambertMaterial`
- 太陽→地球方向の`DirectionalLight`＋控えめな`AmbientLight`
- 地球の自転: 実際の地軸傾斜23.44度、24秒/1回転（アプリの24hシミュレーション換算「実時間1秒=1時間」に合わせた速度）。自転軸をデバッグ表示中
- カメラ位置・注視点・距離・方位角/極角を表示する常時UIテキスト（画面左下）
- カメラの「向き」だけをメインカメラと同期する、固定サイズ・固定位置のミニ座標軸ギズモ（画面右下、独立した`THREE.WebGLRenderer`）
- 天体名ラベル: 画面上で常に一定サイズ・常に手前表示、天体の実座標との対応を示す引き出し線、ラベル同士／ラベルと天体本体の重なりを毎フレーム衝突判定で解消

## 実装中に見つけて直した不具合（今後の類似実装での注意点）

1. **単一天体フォーカスがアスペクト比を見ていなかった**: 縦方向FOVだけで距離を計算しており、縦長画面で横にはみ出す不具合があった。縦横両方のFOVを見て厳しい方を採用するよう修正。
2. **複数天体フレーミングで奥行き差を無視していた**: 中心より手前にある天体は同じ横ズレでも遠近法で画面上大きくズレて見えるのに、それを計算に入れておらず画面に収まらないことがあった。
3. **`.fullscreen-btn`クラスの誤爆**: 見た目を揃えるためだけに独自ボタンへ`fullscreen-btn`クラスを付けたところ、`main.ts`の汎用フルスクリーン配線（クラス名だけで選択）が誤って反応した。`data-target`属性の有無でセレクタを絞って対処。
4. **非表示中に生成したcanvasがゼロサイズになる**: `display:none`の親を持つ要素は`clientWidth/clientHeight`が0になる。固定サイズの要素はレイアウト依存の値を使わず、HTML属性の固定値を直接使うようにした。
5. **OrbitControlsの「ダンピングを一旦切って同期」処理が逆効果だった**: 残存回転量(`sphericalDelta`)を抑えるつもりが、`enableDamping=false`にすると全量が一気に適用される仕様（ソース確認済み）で、直前にドラッグ操作していると意図しない回転が起きた。`camera.lookAt()`を直接呼ぶだけのシンプルな実装に変更。
6. **ラベル位置決めロジックの試行錯誤**: 天体ごとの固定オフセット方向 → グローバル重心基準の外向きオフセット、といずれも不十分だった（後者は2天体選択時に破綻し、近接する2天体が同じ方向に押されて重なる問題を解決できない）。最終的に、ラベルは天体の実座標を起点とし、ラベル同士・ラベルと天体本体の重なりをペアごとの円形衝突判定で毎フレーム解消する方式に落ち着いた。判定は「視線からの角度のtan」空間で行い、距離による遠近を正しく考慮している。
