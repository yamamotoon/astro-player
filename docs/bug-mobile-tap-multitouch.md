# バグ票: マルチタッチ中に意図しないタップ判定が起きる

## 状態

**修正・検証済み**

## 発生バージョン

コミット `2e97943`（feat: スケールモデルの選択/フォーカス操作を刷新、矩形選択モードを廃止）で
`onPointerDown`/`onPointerUp`によるタップ判定を導入した際に混入。それ以前はこのタップ判定の
仕組み自体が存在しなかった（ブラウザのclickイベントで選択/フォーカスを行っていた）。

## 発生方法（再現手順）

1. 指A（`pointerId`=A）で`pointerdown`
2. 指Aを離す前に、指B（`pointerId`=B）で`pointerdown`（2本指操作の開始。ピンチズーム/パンなど）
3. 指Aを先に`pointerup`（指Bはまだ触れたまま）

この時、天体の位置と指A/指Bの座標の組み合わせによっては、意図せず選択/フォーカスが発火する
可能性がある。天体の当たり判定に偶然重なるかどうかに依存するため、手作業での目視再現は運任せに
なる。確実な再現には、実際のイベント列をコードレベルで発生させて検証する必要がある。

## 調査

- `node_modules/three/examples/jsm/controls/OrbitControls.js`を確認。OrbitControls自体は
  `pointers.push(event.pointerId)` / `pointers.splice(...)`（1454-1468行目）で指ごとに
  `pointerId`を区別しており、マルチタッチを正しく処理している。バグはOrbitControls側ではない。
- `scaleModel3d.ts`の`onPointerDown`/`onPointerUp`（タップ/選択判定用、2e97943で新規追加）を確認。
  こちらは`pointerId`を見ずに単一の変数`pointerDownPos`へ、最後に発生した`pointerdown`の座標を
  無条件に上書きしていた。

## 調査結果（原因）

`pointerDownPos`が指を区別しない単一の変数だったため、上記の再現手順の手順3（指Aの`pointerup`）
の時点で、`pointerDownPos`には（手順2で上書きされた）**指Bの座標**が入っている。そのため
「指Aがどれだけ動いたか」ではなく「指Aの現在地と指Bの開始地点との差分」を移動量として計算して
しまい、これがタップ判定の閾値(6px)以内に収まると、意図しないタップとして扱われる。

## 直し方

- `pointerId`ごとに開始位置を追跡する
- 2本目以降の指が触れた時点で、その一連の操作は「タップ候補」から除外する（どちらの指が
  先に離れても、以降タップとして扱わない）
- ブラウザ側の都合でタッチが打ち切られる`pointercancel`でも、カウント/候補を正しく後始末する
  （しないと`activePointerCount`が狂ったままになり、以降タップが一切効かなくなる）

## 修正（適用状況）

`scaleModel3d.ts`の`pointerDownPos`（単一変数）を`tapCandidate`（`pointerId`付き、2本目の指が
触れると`null`化）+ `activePointerCount`に置き換え、`pointercancel`ハンドラを追加。
**ワーキングツリーに変更を適用済みだが、コミット・検証はまだ**。

## 検証（実施済み）

`git show 2e97943:src/scaleModel3d.ts`で取り出した修正前の`onPointerDown`/`onPointerUp`と、
現在のワーキングツリーの修正後のロジックを、それぞれ`this.xxx`→`obj.xxx`の機械的な置換のみで
そのままNode上に再現し（ロジックは書き直していない）、同一のイベント列を流し込んで比較した。

| シナリオ | 内容 | 修正前 | 修正後 |
|---|---|---|---|
| 1: バグ再現条件 | 指Aが実際には400px以上動かしている(本来タップではない)のに、指Bの開始位置がたまたま指Aの終了位置の近くにある | `handleTap`が誤って発火 | 発火しない |
| 2: 通常の単独タップ | 1本指のみでほぼ動かさずdown→up | `handleTap`が発火 | 発火する（機能維持） |
| 3: 通常のドラッグ | 1本指のみで大きく動かしてdown→up | 発火しない | 発火しない（機能維持） |
| 4: 2本指操作後の状態リセット | 2本指操作(down A→down B→up A→up B)の直後に通常の単独タップ | - | 2本指操作中は発火せず、直後の単独タップは正しく発火 |
| 5: pointercancel後の状態リセット | 指がpointerupを経ずにpointercancelで打ち切られた直後に別の単独タップ | - | 打ち切り後の単独タップが正しく発火（カウントが狂って詰まらない） |

シナリオ1で修正前は実際に`handleTap`が誤発火し（バグの再現）、修正後は発火しないことを確認。
シナリオ2・3で修正によって通常のタップ/ドラッグ判定が壊れていないことも確認。
シナリオ4・5で、2本指操作や打ち切りの後も内部状態(`activePointerCount`/`tapCandidate`)が正しく
リセットされ、以降のタップ判定が詰まらないことも確認した。
